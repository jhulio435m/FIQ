# Database Migrations — FIQ Project

## Stack
- SQLModel + SQLAlchemy 2.0 async runtime
- Alembic for migrations
- PostgreSQL 17

## Creating a Migration
```bash
cd backend
UV_CACHE_DIR=/tmp/fiq-uv-cache uv run alembic revision --autogenerate -m "description"
UV_CACHE_DIR=/tmp/fiq-uv-cache uv run alembic upgrade head
```

Review autogenerated migrations before applying. Alembic can miss enum/data/backfill details and can generate destructive changes.

## Models and Seeds
- All SQL models inherit from the established `app.core.database.Base`/SQLModel base pattern.
- Define `__tablename__` explicitly.
- Use `nullable=False` for required fields only when existing data has a safe value path.
- Timestamps should be timezone-aware.
- Keep model, schema, CRUD and seed changes synchronized.
- Use existing seed modules under `backend/app/core/seed*.py`; do not create a parallel seed system unless intentionally replacing the old one.

Required seed data:
1. Roles: `Admin`, `Docente`, `Estudiante`
2. EstadosRecurso: `Pendiente`, `Aprobado`, `Observado`, `Rechazado`, `Archivado`
3. TiposRecurso: `Libro`, `Apunte`, `Guía de laboratorio`, `Tesis`
4. NivelesDificultad: `Básico`, `Intermedio`, `Avanzado`
5. TiposActividad: `login`, `search`, `download`, `upload`, `view`, `lab_access`, `resource_approve`, `resource_archive`, `upload_rejected`, `resource_edit`

## Golden Rules
- Never edit existing migration files after they are committed.
- If you need to change a committed migration, create a new migration.
- Run `alembic upgrade head` before backend development.
- Use `alembic downgrade -1` only for local rollback checks.
- Do not use `Base.metadata.create_all()` as a substitute for Alembic in app startup or production flows.

## Production Safety
- Prefer expand/contract for renames and destructive changes: add new nullable column/table, dual-write/read, backfill, switch reads, then drop later.
- Keep schema migrations and large data backfills separate.
- For existing large tables, create indexes concurrently where possible and document Alembic transaction handling.
- Avoid adding `NOT NULL` without a default/backfill path on populated tables.
- Dropping columns/tables requires a prior app deploy that no longer reads them.
- Every migration must have a local rollback plan, even if production rollback is forward-only.

## Verification
```bash
cd backend
UV_CACHE_DIR=/tmp/fiq-uv-cache uv run alembic upgrade head
UV_CACHE_DIR=/tmp/fiq-uv-cache uv run --extra dev pytest
```
